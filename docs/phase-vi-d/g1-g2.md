# Phase VI-D — refined G1/G2 release acceptance criteria

The original G1 (hardware-offload correctness) is split into independently tracked requirements.
G2 (boot/module lifecycle) stays independent and release-blocking. Status vocabulary: PASS / FAIL /
BLOCKED / UNKNOWN / NOT RUN / UNSUPPORTED.

## G1a — SADR correctness with acceleration disabled

**Requirement:** the SADR invariants hold on the target with acceleration proven disabled (effective
state 0, hooks detached) across A1/B/A2, route/rule transitions and the dataplane matrix.

**Status: BLOCKED / NOT RUN.** The VI-D R1 ran with HWNAT enabled (proc `1`) and acceleration
**UNKNOWN**; it does not prove the traffic was software-forwarded. No target experiment with
acceleration proven disabled has run. Closes only with the maintenance-window request C (or an
authorized dedicated environment). Source analysis and generic-Linux tests do not close it.

## G1b — Reliable detection of unsupported acceleration state

**Requirement:** the product distinguishes configured, driver, effective and unknown acceleration
state and reports it in operational status.

**Status: implementation PASS (off-device), target deployment NOT RUN.** The detector
(`src/lib/EdgeOS/IPv6SADR/Acceleration.pm`) reads the EdgeOS configuration and the effective hook
interface and classifies compatible/incompatible/inconsistent/indeterminate. Unit tests cover the
state matrix and the status exposure (23 tests). Target read-only facts match the classification
(config `hwnat enable`, proc `1`); a deployed-package qualification is not authorized in this phase.

## G1c — Safe initial activation refusal

**Requirement:** the first SADR policy is not activated when HWNAT is enabled or its effective state
is indeterminate; the error is explicit and no partial policy is installed.

**Status: implementation PASS (off-device), target deployment NOT RUN.** `reconcile` refuses before
plan/apply when no SADR-managed objects exist and the state is not compatible; the unit test proves
the refusal leaves no routing mutation. Target deployment is not authorized.

## G1d — Incompatible runtime transitions

**Requirement:** enabling HWNAT while SADR is active must be prevented, or its handling documented;
existing protections are preserved and the violation is reported critically.

**Status: BLOCKED / PARTIAL.** Handling is implemented: existing rules/guards are preserved, a
`CRITICAL` message is logged, and health reports `unqualified` (exit 10) with
`compatibility_violation: 1`. **Prevention is not established:** the vendor `system offload` commit
cannot be vetoed without modifying vendor templates or adding a global hook (not authorized).
Race-free prevention remains a qualification gate; until then, a commit that enables HWNAT can only
be detected at the next reconcile.

## G1e — Correctness of accelerated SADR (only if claimed)

**Status: UNSUPPORTED CAPABILITY.** HWNAT-enabled SADR is not a v0.1.0 requirement. This
classification is a product-boundary decision, not target-platform qualification; accelerated
correctness must not be claimed.

## G2 — Boot/module lifecycle

**Status: BLOCKED (independent).** `CONFIG_IPV6=m`; the boot window, module-reload state and early
guard ordering remain unverified on hardware. G2 is not affected by the G1 split and remains
release-blocking.

## Rules

- Source analysis or generic-Linux testing does not close G1a–G1d on the target.
- Maintainer approval of the unsupported-mode decision is not target qualification.
- No release claim may state that HWNAT-enabled SADR preserves the invariants.
