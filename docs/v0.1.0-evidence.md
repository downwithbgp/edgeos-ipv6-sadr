## 2. Test evidence

### L0 — unit, property and failure injection

`make test-unit` runs 10 `Test::More` files: **619 assertions, 0 failures**.

Covered: IPv6 normalization and host-bit rejection; source/internal prefix safety; desired-state
validation and canonical generation; deterministic table allocation; longest-source-prefix
priorities; ownership refusal; planning determinism and idempotency; disabled creation; prefix
shrink ordering; exception removal ordering; missing tables/defaults; health states and exit codes;
boot-guard parsing/install/orphan cleanup; template and service structure; failure injection at every
mutation boundary; process kill at representative boundaries; persistence failure; foreign-state
preservation; 40 generated property iterations over valid configuration/kernel-state combinations.

The suites exposed and fixed real defects: method/function mismatch in link-local detection, bitwise
precedence in link-local checks, non-deterministic same-phase plan ordering, abort-instead-of-retry on
a configuration generation change, ownership diagnostics that assumed raw `ip` text, and missing
lazy loading of the health collaborator for direct library reconciliation.

### L1 — generic-Linux namespace lab

`REQUIRE_NETNS_TEST=1 make test-netns` runs the PoC, a production phase and the R1 canary simulation:
**145 pass / 0 fail** plus **R1 simulation 10/0**, including **75 packet-path probes** with PA/PB
captures.

The production phase drives the real CLI and kernel with a local JSON config-API fixture. It covers:
boot-guard terminal guards and pre-reconcile blocking; initial reconciliation; exact rule/table/guard
assertions; correct-provider paths; wrong-provider zero-packet checks; internal destinations; nested
source precedence; provider transfer networks; UDP/TCP; established TCP and UDP flows during a
concurrent provider-b update; provider route loss; internal route withdrawal; complete provider and
internal table disappearance; disable; foreign-state refusal; monitor event repair, stop and restart;
policy deletion and native-routing restoration.

This is **Verified (generic Linux)**. It does not establish EdgeOS 3.0.1, kernel 4.14.54-UBNT,
hardware offload or ER-X behaviour.

## 4. Target emulation status

The MIPS PIE / `mmap_min_addr` emulation limitation remains unresolved at the artifact/toolchain
layer: no exact firmware rootfs/userspace, no `qemu-mipsel`, and only MIPS binutils are available.
Security settings were not weakened. No emulated EdgeOS configuration-engine evidence was produced.
Generic-Linux iproute2 parity is 9/9 (`make test-target-parity`), but target iproute2/kernel
behaviour remains **Unverified**. Details: `docs/target-emulation-investigation.md`.

## 4a. Independent review

Independent correctness and security reviews of the full feature-branch diff were completed. Findings

Residual, documented limits: the maintainer scripts retain explicitly documented test-only

environment); target configuration-API absence semantics and target iproute2 `proto`/table-error
rendering remain Unverified; and the no-hardware/no-release gates are unchanged.

## 5. Known limitations and gates

- The terminal guard cannot protect against arbitrary privileged deletion of all SADR rules/tables
  or malicious foreign state. That is outside the threat model.
- The boot window before the early guard, guard failure propagation, and the handling of a
  missing/malformed/unreadable `/config/config.boot` or a failed first guard install are named
  non-guarantees until hardware qualification; see `docs/boot-safety-review.md`.
- The target configuration engine (priority 500, working/active visibility, delete, commit-confirm)
  and service ordering are not target-verified.
- Hardware offload correctness with multi-table RPDB is unverified and is a functional gate, not a
  performance-only concern.
- Source selection for unbound router-originated traffic is not managed; no optimal-source claim.
- CI workflow execution, hardware throughput and target resource consumption are unverified.
- Migration of the manual table `41913` / rules `10410–10414` is not authorized or executed.
- Phase V-C A1 baseline: Stage 0/1 passed on the real ER-X, but A1 delivered 0/20 matching and
  0/10 control because the production IPv6 firewall (`SERVERv6_IN-30`) drops server-VLAN
  destinations in `IPV6_LOCAL_NETS` (drop counter +30). No production mutation was attempted;
  R1 is not run. See `docs/r1-execution-evidence.md`.

See `docs/hardware-qualification-plan.md` and `docs/migration-plan.md` for the gated next steps.
